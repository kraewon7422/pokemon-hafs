# 설계 문서 (DESIGN.md) — v3

> 모든 팀원(과 팀원의 Claude)은 기능을 만들기 전에 이 문서를 읽는다. 바꾸려면 PR로 이 문서부터 고친다.

## 1. 게임 한 바퀴
1. 학교 곳곳의 **QR 포인트**를 앱 하단 가운데 **볼 버튼**으로 찍는다 → 폰 안에 **티켓**이 생긴다 (인터넷 불필요). 그 QR은 티켓을 쓸 때까지 **잠김**.
2. 티켓은 **가방**에 최대 5장. 인터넷이 잡히면 자동 업로드.
3. **메인 부스**에서 폰의 "가방 QR" 하나를 찍는다 → 부스 화면에 **전체 이름·학번** 확인 → 스태프 [확인] → 서버가 티켓 전부를 한 번에 처리:
   QR별 확률표로 몬스터 뽑기 → 도감 추가 → 티켓 사용 처리 → 그 QR **다시 열림**.
4. 부스 화면: 볼 흔들림(또는 GIF) 연출 → "축하합니다! ○○몬을 획득했습니다!"
5. 학생 폰: 축하 + **퀴즈** 바텀시트 (그 쌤 문제, 학생당 같은 문제 반복 없음). 정답 → **진화권 +1** (100%).
6. **도감**에서 몬스터를 눌러 진화권 사용 → 서버가 확률로 진화 (1→2: 70%, 2→3: 35%, 실패할수록 확률↑, 일정 횟수 실패 시 확정).
7. 랭킹: 단계 점수 합 (1단계 1점 / 2단계 3점 / 3단계 6점, 희귀 +2, 전설 +10). 동점은 먼저 도달한 사람.

- "도망쳤다" 실패는 **없다**. 확률은 "무엇이 나오는가"에만.
- **전설** = 교장쌤·교감쌤, **진화 없음(1단계)**. 대형 TV의 30초마다 바뀌는 QR로만 잡힘 (`lines.max_stage = 1`).
- 도감 = 일반 15라인 × 3단계 + 전설 2 = 47칸 (라인 수는 운영자 페이지에서 조정).

## 3. 오프라인 원칙
- 인터넷 없이 되는 것: 앱 열기, 도감·지도·랭킹(마지막 저장본) 보기, **QR 스캔**, 가방 QR 보여주기.
- 인터넷이 필요한 것: 첫 로그인, 퀴즈 제출, 진화, 랭킹 갱신. (버튼은 비활성 + 이유 표시. 무한 로딩 금지.)
- **전설 QR은 찍고 90초 안에 서버에 도착해야 인정** → 인터넷 연결 상태에서 찍어야 한다.
- 폰은 IndexedDB에 `snap`(서버가 준 마지막 상태) + `outbox`(아직 못 보낸 스캔)를 저장. 화면 = 둘을 합친 것.
- outbox 항목은 서버가 **nonce별 결과(ack)**를 줘야만 지운다.
- 부스는 학생 폰이 오프라인이어도 처리 가능: 가방 QR 안에 티켓 정보가 다 들어 있다.
- 동기화: 화면이 켜져 있을 때 60초마다 + 앱으로 돌아올 때 + 스캔 직후. 가방 QR을 띄운 동안만 3초마다.
  `sync(p_ver)` — 바뀐 게 없으면 서버가 아주 작은 응답(`same: true`)만 보낸다 (데이터 전송량 절약).

## 4. 데이터 형식 (바꾸지 말 것 — 바꾸면 인쇄된 QR이 다 죽는다)
- **장소 QR**: `https://<사이트>/s#<QR_ID>.<TOKEN>` (예: `/s#A07.k3x9p2mq`). QR 아래에 5자리 수동 코드 인쇄.
  포스터에 **"앱의 볼 버튼으로 찍으세요!"** 문구 필수 (폰 기본 카메라는 다른 브라우저로 열릴 수 있음).
- **가방 QR (v2)**: `PH1/<학번>/<NONCE>.<QR_ID>.<TOKEN>/...` — **대문자·숫자·`.` `/` `-`만** 사용
  (QR 영숫자 모드 → 작고 빨리 읽힘, USB 스캐너가 한글 입력 상태여도 부스가 자모→영문 복원). `-` = 수동 코드 티켓. v1(`|` 구분)도 계속 읽힘.
- 로그인 (0008~): **아무 구글 계정** → 첫 로그인 때 등록 화면에서 **학생(고유번호 6자리 + 이름)** 또는 **외부인(이름만, 랭킹 제외)** 선택 (`register_profile`). 고유번호 `022001` = 22기 1번.
- 학번 로그인: 학번만 입력 → 서버가 `<학번>@code.local` 계정과 8자리 코드를 만들어 **한 번만** 보여 줌 (`create_code_account`, 10분당 생성 수 제한). 다음부터 학번 + 코드. 운영자가 인쇄한 코드(`admin_make_login_codes`, T01 등 → `g:t01`)도 그대로 동작.
- 계정은 서버 함수로만 만든다. Supabase 공개 이메일 가입을 열지 않는다 (남의 이메일 선점 → 구글 로그인 때 계정 탈취 위험). 운영자/부스 권한은 구글로 확인된 이메일에만 (`@staff.test`는 테스트 예외).
- 학번은 본인 입력이라 남이 먼저 등록할 수 있다 → `STUDENT_ID_TAKEN`이면 부스에서 운영자가 재연결, **상품은 학생증 확인 후 지급**.
- 개발용 로그인: 설정 `dev_login`이 true일 때만, 아무 이메일 + 비밀번호 `1234abcd!` (`dev_create_account`).
- 로그인 유지: 세션은 폰에 저장되고 1시간짜리 토큰이 자동 갱신된다. 앱은 오류로 로그아웃하지 않는다 (만료 토큰 → `refreshSession` 후 재시도, `NO_PROFILE` → 등록 화면, 그 밖 → 다시 시도 화면). 로그아웃은 `scope: 'local'` (다른 기기 로그인 유지).
- 고유번호 계정 (0011): 게임 계정 = `<고유번호>@code.local` 사용자 하나. 비밀번호는 학생이 직접 정함(6자 이상).
  - 구글 없이: 번호 + 비밀번호 → 없으면 `create_number_account` 로 만들고 로그인, 있으면 비밀번호 확인.
  - 구글 → 학생: `link_number(번호, 비밀번호, 이름)`. 처음 쓰는 번호면 지금 구글 사용자가 그대로 번호 계정이 됨(mode new). 이미 있으면 비밀번호 확인 후 그 구글 identity 를 번호 계정으로 옮기고 빈 사용자를 지움(mode linked → 클라이언트가 번호+비밀번호로 다시 로그인). 이후 그 구글 계정 로그인 = 같은 번호 계정.
  - 학교 구글 계정(Google 이 확인한 이메일 `022001@hafs.hs.kr`): 등록 화면에 번호 자동 입력, 자기 번호면 비밀번호 즉시 재설정(`p_reset`, 다른 기기 로그아웃 + 다른 구글 연결 해제).
  - 비밀번호 분실: `request_password_reset`(새 비밀번호를 미리 받아 해시로 보관) → 운영자 요청 탭 허용 시 적용 + 로그아웃 + 구글 연결 해제. **허용 전 학생증 확인** (이름은 남도 앎).
  - 부계정은 '외부인'(번호 없음, 랭킹 제외). 구글 사용자의 `register_profile(student)` 는 `USE_NUMBER_LOGIN` 으로 막힘.
- 이스터에그: ① 제목 7번 탭 → 몬스터 퍼레이드 ② 비밀 QR `S01`(지도·카탈로그에 안 보임) → 비밀 몬스터 라인 37 숨바꼬치(도감 완성 조건에서 제외) ③ 도감 완성 → 한 번 축하 화면 + 금테 카드 + 칭호 '도감 마스터' ④ 정각(00분)·마감 1분 전 획득 → 황금 연출 ⑤ 룰렛 꽝이 드물게 777 → 칭호 '럭키 세븐'(서버 `profiles.titles`).
- 참여 기수 (0010): `settings.allowed_gens` = [20,21,22]. 학번 앞 세 자리 = 기수. 범위 밖이면 BAD_GEN (profiles 트리거가 모든 가입 경로를 막음). 앱 ⚙ 설정 맨 아래에 운영자 페이지(admin.html) 링크.
- 운영진 초대 (0009): 운영자 페이지 운영진 탭 → 구글 이메일 + 역할(운영자/부스) → `settings.admin_emails/booth_emails`. 이미 로그인한 구글 계정은 즉시, 아니면 첫 로그인 때 권한. 내 역할은 스스로 못 바꿈.

## 5. 서버 규칙 (보안·동시성)
- 학생은 테이블에 **직접 쓰지 못한다.** 모든 변경은 서버 함수(RPC)로만.
- 모든 변경 RPC: `SECURITY DEFINER`, `search_path=''`, 시작하자마자 그 학생의 `profiles` 행을 `FOR UPDATE`로 잠금 → 같은 학생 요청은 한 줄로 처리 → 중복 지급 불가.
- QR 토큰(`qr_secrets`)·퀴즈 정답(`quiz_answers`)은 학생이 읽을 수 없는 별도 테이블.
- (학생, QR)당 미사용 티켓은 최대 1장 (부분 유니크 인덱스) = 잠금. 하루 같은 QR 최대 `qr_points.daily_cap`(없으면 `settings.qr_daily_cap`)회 — 희귀·전설 QR은 1회.
- 미사용 티켓은 `ticket_ttl_hours` 지나면 만료. 몬스터 후보가 빈 QR의 티켓은 부스에서 취소(잠금 해제) + 현황판 경고.
- 수동 코드 10번 틀리면 10분 잠금. **전설(rotating) QR은 수동 코드 불가**, 토큰은 `rotating_accept_sec`(90초) 동안만 유효.
- 시간 판정은 **서버 시계만**. 같은 가방 QR을 여러 번 읽어도 **처음 결과를 그대로 반환** (멱등).
- 토큰 교체 시 옛 토큰은 `token_grace_minutes` 동안 유효 (이미 찍은 오프라인 티켓 보호).
- `festival_open = false` → 게임 정지 (비상 스위치). `self_redeem = true` → 부스 과부하 때 학생이 앱에서 직접 받기 (안전밸브).
- 나중에 추가하는 함수는 기본으로 아무도 실행 못 함 → 필요한 것만 `grant execute ... to authenticated`.

## 6. 화면 규칙
- **학생 앱**: 에메랄드 픽셀 스타일. 몬스터 64×64, 기기 픽셀 기준 정수배 확대 (`js/sprites.js`, 갤럭시 소수 DPR 대응). 폰트 Galmuri11 (없는 글자는 시스템 폰트로 자동 대체).
- 홈 맨 위 **"다음에 할 일" 버튼 하나**(퀴즈 → 가방 → 진화 → QR 찾기 순). 첫 로그인: 등록 화면(학생/외부인 + 이름, 개인정보 안내, 랭킹 이름 공개 여부 — 기본 공개, "22기 강*원" 가림) → 게임 방법 4장. 이름은 랭킹·TV·부스 어디서나 `강*원`, 전체 이름은 본인 화면과 운영자 페이지에만.
- 폰 화면: 가로로 넘치는 요소 0개가 기준 (360/390/412px 자동 점검). `[hidden]`은 항상 `display:none !important`.
- 앱 설치(PWA): 로그인 화면·홈 위쪽 "앱으로 설치하기" (크롬은 설치 창, 아이폰은 방법 안내). 설치하면 주소창 없이 열림.
- 이름 공개/비공개는 **오른쪽 위 ⚙ 설정** 맨 위에서 언제든 변경.
- 안드로이드 뒤로가기 = 열린 창 닫기 → 이전 탭.
- iPhone 안전영역, 터치 44px 이상, `prefers-reduced-motion` 존중, 초당 3회 이상 번쩍임 금지.
- 카카오톡/인스타 인앱 브라우저 감지 → 외부 브라우저로 열기 안내. 로그인 안 된 브라우저에서 QR 링크가 열리면 "앱의 볼 버튼으로 다시 찍기 / 5자리 코드" 안내.
- **운영자 페이지**: 픽셀 아님, 일반 관리 화면.

## 6-1. 배틀 데이터 (0012 + 0014, `tools/gen_battle_data.py` → `supabase/seed_battle.sql`, 계열 목록 `tools/roster.py`)
- 계열 = 선생님 1명당 1개, 68개 (1~34 처음 계열 + 43~76 명단에 맞춰 늘린 계열) + 전설·비밀 35~42. 실제 선생님 이름은 저장소에 넣지 않는다 (teacher = '국어 선생님 5' 같은 표시).
- 배틀 타입 15개 (`lines.btype`): 국어·수학·영어·물리·화학·생명·지구·지리·정치경제·윤리·역사·외국어·정보·체육·음악 (+ 보통, 전설). 도감 필터·타입 색 그룹은 `subject`(과목), 상성·기술은 `btype`.
- 상성 = 공격 타입 × 방어 타입 표 (`type_chart`, ×1 칸은 없음): ×2 / ×½ / ×0. 효과 없음: 정치경제→음악, 역사→정보, 체육→수학. 타입마다 ×2 2~3개, 약점 2~4개가 되게 맞춤. 전설은 모두 ×1, 전설끼리 ×2.
- 종족값 6개: 타입 성향 × 단계 총합 (300/405/500, 희귀 +15, 전설 520~640). 라인 번호로 고정한 난수로 6개를 각각 ±14% → 같은 능력치 몬스터 없음 (생성기가 검사).
- 기술 157개 (`moves`, 실제 포켓몬 기술 한국어 이름): 타입마다 물리·특수 2~5개(약→강) + 상태기 3 + 방어기 3. 몬스터마다 4개 (`species_moves`: 공격 2·상태 1·방어 1) 를 단계·라인 번호로 골라서 같은 타입끼리도 다르다. 3단계 두 번째 공격 = 커버 기술(나에게 강한 타입을 많이 찌르는 타입).
- 기술 `effect` (jsonb): `foe_status` par/brn/psn/slp + `chance`, `self`/`foe` 랭크 변화(atk/def/spa/spd/spe/acc), `protect`, `endure`, `rest`, `screen` reflect/light, `break_screen`, `heal` %, `drain` %, `recoil` 1/n, `self_damage` %, `high_crit`, `always_crit`, `self_all_up`.
- 레벨 50 고정 능력치: HP = ⌊(2B+31)/2⌋+60, 나머지 = ⌊(2B+31)/2⌋+5. 요약 화면·레이드 데미지가 같은 식.
- `lines.bonus` = 도감 완성·% 계산에서 빠지는 몬스터 (비밀 37, 탐구 전설 38~42).

## 6-2. 레이드 + 특별 티켓 (0013)
- 레이드 QR = 보통 장소 QR 과 같은 모양 `…/s#R<id>.<토큰>`. 앱은 `R숫자` 이면 티켓 대신 `raid_join`. TV 레이드(`raids.tv`)의 토큰 = HMAC(30초 창, raids.token) → 최근 90초 것만 인정 (사진 공유 방지). 인쇄용은 고정 토큰.
- 공격: 폰이 탭을 세어 4초마다 `raid_attack(id, 탭 수, 몬스터)`. 서버는 지난 요청 이후 경과 초 × `raid_tap_cap`(8) + 8 까지만 인정. 화면의 체력바는 아직 안 보낸 탭만큼 미리 깎아 보여 줌. 레이드 행 하나를 모두가 고치므로 보스 체력 갱신은 `greatest(0, hp - dmg)` 한 줄.
- 탭당 데미지 = max(1, round(10 × 내 몬스터(지금 단계) Lv.50 공격/특수공격 중 큰 쪽 ÷ 보스 방어/특수방어 × 상성)). 몬스터가 없으면 3.
- 끝: 체력 0 → `won`, `raid_min_taps`(10) 이상 탭한 참가자에게 보스 특별 티켓. 시간 초과 → `failed` (`_raid_sweep` 이 아무 레이드 호출 때 정리).
- 시간대 전설: TV(`screen_raids`, 3초마다)가 `raid_slots` 시간 안이면 그 전설 레이드를 자동으로 열고, 끝나면 `raid_cooldown_min` 뒤에 다음 판.
- 특별 티켓 `tickets.special` (raid/dex50/dex100) + `fixed_species`: 가짜 장소 RAID/DX50/DX99 (이름이 ★로 시작 → 부스·앱에서 금빛 표시). 가방 5칸·24시간 만료 제외, 부스에서 보통 티켓과 함께 바뀌고 그 몬스터가 그 단계로 바로 들어옴. 도감(보너스 제외) 50% → 과연기, 100% → 창문기 (`_recompute` → `_dex_rewards`, 한 번씩).

## 6-3. 배틀 (0015)
- 계산은 전부 서버 함수 안 (`_bt_move`, `_bt_turn`, `_bt_resolve`). 폰은 `battle_act(id, {"move": 1~4} | {"switch": 0~2})` 만 보내고, 돌아온 `log` 를 재생한다. 상대 몬스터의 기술·대기 몬스터 이름, 상대가 고른 것은 폰에 오지 않는다.
- 3 대 3 싱글, 교체 가능, 쓰러지면 다음 몬스터를 고름 (남은 게 1마리면 자동). 레벨 50, 3세대 데미지 공식, 자속 1.5, 상성 ×2/×½/×0, 급소 1/16(×2), 명중·선공·스피드(마비 ¼), 랭크 ±6, 마비·화상·독·잠듦, 방어·버티기(연속이면 성공률 ½씩), 벽 5턴, 회복·흡수·반동, PP (다 쓰면 발버둥).
- AI (`_bt_ai`): 기술마다 예상 데미지(위력×상성×자속×명중×능력 비) 점수, 쓰러뜨릴 수 있으면 크게 가산. 상태 이상·능력 올리기·회복·벽은 상황이 맞을 때 점수. ±25% 흔들림.
- 종류: `cpu` 연습 (상대 = 내 팀과 같은 단계의 아무 선생님 몬스터, 보상 없음) / `team` 친구 팀 vs AI (친구의 배틀 QR) / `pvp` 실시간 (신청 → 친구 홈에 "배틀 신청!" → 수락. 한 턴 45초, 안 고르면 AI가 대신).
- 배틀 QR = `BTL.<profiles.battle_code>` (보통 QR 과 같은 모양, `?q=` 링크도 됨). 배틀 팀 = `profiles.battle_team` (없으면 가장 높은 단계 3마리).
- 보상: 이기면 진화권 1장 + `battle_wins` +1 (랭킹). 하루(한국 시간) `battle_daily_max`(3)번, 같은 상대는 하루 1번 (`battle_rewards`). 연습은 보상·랭킹 없음.
- 폰: 홈·배틀 탭을 보고 있을 때만 15초마다 `battle_inbox`. 실시간 대전 중에는 2초마다 `battle_state`. 기록 글의 `@0`/`@1` → 내 쪽 '' / 상대 쪽 '상대 '.
- 2 대 2 (0016): `battles.format` single / double. 자리 u = 쪽×2 + 자리 번호, `state.sides[s].act` = 나와 있는 몬스터 번호들. 형식은 배틀 QR 을 보여주는 사람이 고름 (`profiles.battle_format`, `battle_code(p_format)`, 찍은 사람은 `battle_peek`). 팀 1 대 1 = 3마리, 2 대 2 = 4마리 (0045 부터: 형식과 상관없이 배틀 팀 1~6마리, 2 대 2 는 2마리 이상 · AI 는 내 팀과 같은 수 · 친구와는 min(내 팀, 친구 팀) 마리씩 각자 팀 앞에서부터 · 턴 제한은 팀이 크면 비례해서 늘어남). 2 대 2 고르기 = `{"slots": [{move, target} | {switch} | null, …]}`, 네 마리 모두 선공 → 스피드 순, 쓰러진 자리마다 교체.
- 기록 이벤트: `use` [자리, 타입, 분류] · `hp` [자리, HP] · `faint` 자리 · `stat` [자리, ±1] (빨간 줄 위/아래 + 효과음) · `st` [자리, 상태] · `sw` [자리, 번호] + name/sp · `back` 자리 + name. 교체 문장(가랏! / ~는 ~를 내보냈다! / 돌아와! / 들여보냈다!)은 폰이 쪽에 맞게 만든다.
- 실시간 대전 중에는 다른 배틀을 시작할 수 없다 (`IN_PVP_BATTLE`). 몰래 기권되지 않게.
- 화면: 배경 7종 (isaiah658 픽셀 팩 #2, CC0, `web/img/battle/`), 배틀 번호로 고름. 몬스터볼 던지기 → 번쩍 → 등장, 가만히 있을 때 앞뒤로 흔들림, 3세대 느낌 글 상자(남색·금 테두리·빨간 ▼), 직접 만든 8비트 배경 음악 (`sfx.js` startBgm/stopBgm, 소리 끄기 따름).

## 6-4. 로그인과 복구 (0011 + 0018)
- 로그인 화면: 학생 = 고유번호 + 비밀번호 (`<번호>@code.local`), 비학생 = 아이디 + 비밀번호 (`<아이디>@id.local`, 영문으로 시작 4~16자), 맨 아래 구글 = 복구용. 처음 쓰는 번호·아이디면 그 자리에서 계정이 만들어진다 (`create_number_account`, `create_id_account`, 10분당 생성 수 제한 공유).
- 비학생 프로필 = `g:<아이디>`, 랭킹 제외. 아이디 계정은 학생 번호를 가질 수 없다.
- 운영진 = 아이디 계정 + `raw_app_meta_data.staff = true`. 운영자만 만들 수 있고 (`admin_create_staff_login`, 12자리 랜덤 비밀번호를 한 번만 보여 줌), 첫 운영자는 SQL 편집기에서 `bootstrap_staff`. 스스로 만든 아이디는 운영진이 될 수 없고, 운영진 아이디에는 구글을 붙일 수 없다 (비밀번호는 `admin_reset_staff_password`, 그 계정의 로그인을 모두 끊음). 예전처럼 `admin_emails`/`booth_emails` 의 구글 계정도 그대로 됨.
- 복구 (OWASP Forgot Password 지침): 설정 → "복구용 구글 연결" = 로그아웃 → 그 구글로 로그인 → 내 비밀번호 한 번 더 → 구글 identity 가 내 계정으로 옮겨짐 (`link_number` / `link_id`, `_attach_google`). 비밀번호를 잊으면 "구글로 내 계정 찾기" → 그 구글로 로그인하면 내 계정 → 바로 새 비밀번호 (두 번 입력, `updateUser` 후 다른 기기 `signOut({scope:'others'})`). 구글이 없으면 학생은 운영자에게 초기화 요청 (0011), 아이디는 문의하기.
- 처음 구글로 들어온 경우: 학생 → 고유번호 + 비밀번호, 비학생 → 아이디 + 비밀번호로 연결 (그 구글이 복구용이 됨). 개발용 이메일 로그인 칸은 앱에서 없앰.

## 6-5. 성장: 레벨 · 기술 배우기 · 가방 (0020)

## 6-7. PC 박스 (0036)
- `collection` 한 줄 = 포켓몬 한 마리 (`id`). 같은 종도 여러 마리, 각자 레벨·경험치·기술·배운 기술·지닌 물건·반짝·진화 실패 수.
- 박스 = `pos` 0~899 → BOX `pos/30+1` (1~30), 칸 `pos%30` (6열 × 5줄). 새 포켓몬은 빈 칸 중 맨 앞. `box_move(p_mon, p_pos)` 로 옮김 (차 있으면 서로 바꿈).
- 최대 `box_max` 마리 (설정, 기본·최대 900). 꽉 차면 부스는 그 티켓을 쓰지 않고 `box_full` (티켓 그대로) · 야생/사파리/레이드 잡기 · 알 부화 · 운영자 지급은 `BOX_FULL` (만남·알도 그대로) → 놓아준 뒤 다시.
- 놓아주기 `mon_release(p_mon)`: 줄은 지우지 않고 `released_at` 만 적음 (박스·배틀·레이드에서는 안 보임). **도감 '잡은 적 있음' · 점수 · 도감 50/100% 보상 · 도전과제는 그대로** (점수 = 계열마다 가장 높은 단계 하나 — 같은 종을 많이 잡아도, 놓아줘도 같음). 지닌 물건은 가방으로. 마지막 1마리 · 카드 포켓몬 (`partner_mon`) · 저장한 배틀 팀 (`team_mons`) · 진행 중인 배틀(신청 포함)/레이드의 포켓몬은 안 됨.
- 중복 잡기: 그 계열을 잡은 횟수 (`catch_count` 합, 놓아준 것 포함) 가 `dup_bonus_every` 의 배수가 되면 진화의 돌 (예전과 같음). '또 잡으면 그 포켓몬 레벨 +1' 은 없어짐 (새 한 마리가 생기므로).
- sync: `collection` = 도감 (계열마다 한 줄: 가장 높은 단계 · 잡은 횟수 합 · 지금 가진 수 `count`), `mons` = 박스의 포켓몬 (`id, line_id, stage, level, pos, held, shiny, shiny_on, from_egg, evo_fails, caught_at`). `rules.box_max`.
- 함수 인자 = 포켓몬 번호: `evolve(p_mon)` (0037: `evolve(p_mon, p_to)`), `bag_set_held(p_mon, p_item)`, `bag_set_moves(p_mon, p_moves)`, `bag_use(p_item, p_mon)`, `set_partner(p_mon)`, `set_shiny(p_mon, p_on)`, `battle_set_team / battle_start_cpu / battle_start_team / battle_challenge / battle_accept (p_mons bigint[])` (같은 종 두 마리도 한 팀, 같은 한 마리 두 번은 안 됨), `raid_join / raid_join_open / raid_attack (p_mon)`. 운영자 `admin_grant_monster` = 새 한 마리, `admin_set_level` = 그 계열 모두. 배틀 상태의 포켓몬에 `mon`, 레이드 참가자 `mon_id`.

## 6-8. 갈래 진화 · 사파리 도망 · 도감 쪽 (0037)
- 진화 길 = `evolutions` (from_species → to_species, how `level` | `item`, lv). 곧은 진화도 갈래도 모두 이 표 (seed_pokemon.sql 이 만듦). `evolve(p_mon, p_to)`:
  갈래가 둘 이상이면 `p_to` 필수 (`PICK_BRANCH`), 그 종의 갈래가 아니면 `BAD_BRANCH`. 규칙은 0034 그대로 — level: `lv` 이상이면 진화의 돌 없이 100%, 전에는 진화의 돌 + 확률 / item: 진화의 돌 1개로 100%.
- 갈래 종 = `species` 줄 하나 더 (id = 10000 + 전국도감 번호, 원래 계열 · 다음 단계). 따로 1단계 계열로 있던 같은 포켓몬 (야생 쥬피썬더, 전설 계열 425 루나아라 …) 은 그대로 → 야생에서 바로 만날 수도 있음.
  그림은 같은 번호의 종 그림 (`sprites.js aliasSprites`). 갈래 종의 레벨 기술은 계열의 배우는 기술에 합침 + 그 종의 고른 기술 4개.
- `collection.species_id` = 그 포켓몬의 지금 종. 트리거 (`_col_species`) 가 (계열, 단계) 와 맞지 않으면 그 단계의 첫 종으로 맞춤 → 진화만 갈래 종을 적음.
- **도감 = 전국도감 번호마다 한 칸.** 본 적 있는 종 = 가진 (놓아준 것 포함) 포켓몬의 지금 종 + 앞 단계들 (`_sp_path`, sync 의 `seen`). 같은 번호면 어느 길로 만나도 발견.
  `dex_count` = 발견한 번호 수. 학교 도감 (50/100% 보상) = 선생님 · 특별 계열 종의 번호 213칸 (갈래 7: 엘레이드 · 왕구리 · 홍수몬 · 카포에라 · 야도킹 · 눈여아 · 아르코 포함) → 100% 는 갈래까지 모두 진화시켜야 함.
  점수는 예전처럼 계열마다 가장 높은 단계 하나.
- 사파리존 도망 = **서버가 정함** (3세대처럼): 공을 놓칠 때마다 앱이 `safari_turn(p_id)` → 도망칠 확률 = `safari_flee` (25%) + 놓친 차례마다 `safari_flee_step` (+5%) + 전설 `safari_flee_legend` (+15%), 최대 `safari_flee_max` (90%).
  도망치면 그 만남은 끝 (던진 볼 = 놓친 수). 앱이 `safari_turn` 을 건너뛰고 '잡았다' 고 보내도 `safari_result` 가 아직 안 굴린 놓친 공의 도망을 굴림 (`server_fled`). 잡힐지는 예전처럼 앱이 정함 (볼 수는 서버가 셈).
- 사파리볼 충전: `safari_balls_daily` (기본 20개, 운영자 화면 − 숫자 +) 와 만남 수 `safari_daily_max_encounters` 는 **충전 주기마다** 다시 참.
  주기 `safari_reset_hours` (1~24, 기본 24, 운영자 화면 1/3/6/12/24시간 단추) = 서울 00:00 부터 그 시간마다 (6 → 00·06·12·18시, 24의 약수가 아니면 자정에서 끊음).
  `safari_days` 는 충전 구간 시작 (`period_start`) 마다 한 줄 — 볼은 만난 때의 구간에서 뺌. `safari_state` = `balls` · `max_balls` · `reset_hours` · `period_start` · `next_reset_at` (앱: '다음 충전 15:00').
- 도감 화면: 전국도감 번호 순 60칸씩 쪽 (◀ 1/14 ▶ + 번호 범위, 위·아래), 지방 바로 가기 (관동 1 · 성도 152 · 호연 252 · 신오 387 · 하나 494 · 칼로스 650 · 알로라 722). 범위 · 타입을 바꾸면 첫 쪽.

## 6-9. 전설 · 알림 · 퀘스트 · 방랑 전설 · 이상한 소포 · 울트라비스트 · 메타몽 (0038)
- **알림 (`notices`)**: 특별한 보상마다 한 줄 (user_id, kind, species_id, title, body, data, seen_at). 특별 티켓 (도감 50/100% · 레이드 · 숨은 선물 · 소포 · 전설 · 방랑 · 사파리/야생 전설) 이 생기면
  트랜잭션 끝 (deferred constraint trigger `tickets_notice`) 에 그 티켓의 지금 상태로 글을 씀 — 바로 박스로 갔으면 "박스에 들어갔어요", 남았으면 "티켓 주머니 … 부스에서".
  퀘스트 티켓 · '깨어났다' · 물건 소포는 함수가 바로 씀 (같은 sync 에서 보이게). `sync.state.notices` = 안 본 것 20개, 앱 `legends.js playNotices()` 가 하나씩
  전체 화면 연출 (어두움 → ! → 그림자 → 번쩍 · 색 · 반짝이 + `sfx.fanfare`, 배경 음악은 잠깐 조용히, 효과음 스위치를 따름) → `notice_seen(ids)`. 기기에도 본 id 를 적어 두어 다시 틀지 않음.
  다른 화면 (잡기 · 축하 · 시트) 이 떠 있으면 끝난 뒤에. 연출 뒤 관계있는 탭 (티켓 주머니 = 홈, 깨어남 = 지도, 그 밖 = 도감) 에 ★ → 그 탭을 열면 사라짐.
- **퀘스트 전설**: `settings.legend_quests` (운영자 '전설·소포' 탭에서 숫자). kind = quiz_streak (가장 긴 연속 정답) · battle_wins · catches (잡은 포켓몬, 알 제외) · raid_slots (참가한 레이드의 서로 다른 시작 시각)
  · qr_all (지도에 보이는 장소 QR 모두) · type_catch (types 중 하나라도 맞는 타입, 놓아준 것 포함) · safari_catches · caught_all (of 의 전설을 모두 잡음).
  기본: 유크시 퀴즈 10연속 · 엠라이트 배틀 10승 · 아그놈 30마리 · 디아루가 시간대 레이드 3 · 펄기아 모든 장소 QR → 특별 티켓 (special 'quest', 부스에서) ·
  레지락 바위 8 · 레지아이스 얼음 5 · 레지스틸 강철 8 · 레지기가스 셋 모두 · 루기아 물 20 · 칠색조 불꽃/비행 20 · 가이오가 사파리존 15마리 · 그란돈 땅 15 · 레쿠쟈 가이오가+그란돈 → 사파리존 지도 자리.
  한 번 채우면 `legend_quest_done` (숫자를 올려도, 연속이 끊겨도 그대로). 진행 = `sync.legends` · `safari_state.legends` (cond · prog "퀴즈 연속 정답 7/10" · ok · caught · seen) → 사육사 · 전설 자리 (`hintsFromServer`).
  이 줄들 (lines.legend_src quest/safari/roam/gift) 과 울트라비스트 (lines.ultra) 는 보통 야생 · QR · 걸음 · 사파리 풀숲에 안 나옴.
- **사파리존 전설 만남** = `legend_encounter(p_dex)` (조건 확인 `NOT_READY`, 이미 잡음 `ALREADY_CAUGHT`, 하루 `legend_daily_tries` 번 `NO_TRIES`, 30분 안의 같은 만남은 이어서) →
  raid_encounters kind 'legend' (HAFS 볼 `legend_balls`, 포켓몬 GO 처럼 다 빗나가면 도망 — 자리에 남아 다시 도전) → `legend_result` (끝난 만남은 적어 둔 결과 = replay). 홈 배너에는 안 나옴.
- **방랑 전설** (라이코 · 앤테이 · 스이쿤): `_roam_spot(dex, 시각)` = 지도에 보이는 장소 QR 중 md5(`roam_seed` · 번호 · 서울 시각의 시) 가 가장 작은 곳 — 같은 시간이면 늘 같은 곳, 학생은 모름.
  새로 찍은 장소 QR 이 그곳이면 (sync) `roam_chance` (30%) 로 kind 'roam' 만남 (홈 배너, 몬스터볼 `roam_balls`). 그 전설을 잡았으면 다시 안 나옴, 한 시간에 한 번 기회.
  `sync.roamers` 소문 = 건물 (P홀 · D홀 … 근처) 또는 지도 쪽 ("지도 가운데 어딘가") — QR 지도 위에 '소문' 상자. 운영자: `admin_roam_spots(p_at)`.
- **이상한 소포**: `gift_codes` (code = 띄어쓰기 빼고 소문자, 포켓몬 (도감 번호, 1~6마리) 또는 물건 (items.key · 'evo_stone' = 진화의 돌, 1~99), 시작 · 끝, 최대 받는 사람, 켜기/끄기), `gift_claims` (한 사람 한 번).
  학생: 위 막대 설정 단추 왼쪽의 소포 단추 (받을 수 있는 소포가 있으면 ★ — `sync.gifts_open` 은 수만) → 코드 → `gift_claim(p_code)` → `{ ok, … }` 또는 `{ ok:false, error }`
  (BAD_GIFT · GIFT_EXPIRED · GIFT_NOT_YET · GIFT_CLAIMED · GIFT_GONE · TRY_LATER = 10분에 `gift_fail_limit` 번 틀림). 포켓몬은 special 'gift' 티켓을 바로 바꿈 (박스가 꽉 차면 티켓 주머니에 남음), 잡기 장면 없이 알림 연출.
  환상의 포켓몬 13종 (지라치 · 테오키스 · 쉐이미 · 비크티니 · 다크라이 · 케르디오 · 게노세크트 · 디안시 · 후파 · 마기아나 · 마샤도 · 제라오라 · 멜탄) = 소포로만.
- **울트라비스트 · 구역**: `safari_encounter(p_steps, p_zone)` — 앱이 걸은 칸의 구역 (`zoneAt`) 을 보냄. 'ultra' = 울트라비스트만, 'cave' · 'deep' = 바위 · 땅 · 고스트 · 악 · 강철 · 물 타입 × `safari_cave_type_mult` (4),
  'grass' · 모르는 값 = 보통 야생. 구역은 앱 말을 믿는 것이지만 울트라비스트는 ultra 에서만 (다른 구역에서는 절대 안 나옴).
- **메타몽 변신**: 야생 (걸음) · QR 야생 · 사파리 잡기에서 `ditto_disguise_chance` (기본 0.5%) → 메타몽 (dex 132) 으로 들어옴, `tickets.disguised_as` = 원래 종.
  결과 `{ ditto: true, disguised_as }` · QR 은 `sync.disguised[nonce]` → 앱: 변신한 모습으로 잡기 → "……?" → 도트가 흩어지며 메타몽 → "OO는 사실 메타몽이었다!". 전설 · 선생님 · 특별 티켓 · 레이드 · 소포에는 없음.
- **사파리 고침**: 지난 충전 구간의 끝나지 않은 만남은 `safari_state` · `safari_encounter` 때 도망으로 정리 (볼 = 던진 수 `throws` 만, 그 옛 구간 몫). 앱은 던질 때마다 `safari_throws(p_id, p_n)` (줄지 않음).
  `safari_result` · `legend_result` 를 끝난 만남에 다시 보내면 `raid_encounters.result` 에 적어 둔 결과 + `replay: true` (볼을 더 쓰지 않음). 시험용 `admin_encounter_age(p_id, p_minutes)`.
