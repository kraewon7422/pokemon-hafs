# 설계 문서 (DESIGN.md) — v3

> 모든 팀원(과 팀원의 Claude)은 기능을 만들기 전에 이 문서를 읽는다. 바꾸려면 PR로 이 문서부터 고친다.

## 1. 게임 한 바퀴
1. 학교 곳곳의 **QR 포인트**를 앱 하단 가운데 **볼 버튼**으로 찍는다 → 폰 안에 **티켓**이 생긴다 (인터넷 불필요). 그 QR은 티켓을 쓸 때까지 **잠김**.
2. 티켓은 **가방**에 최대 5장. 인터넷이 잡히면 자동 업로드.
3. **메인 부스**에서 폰의 "가방 QR" 하나를 찍는다 → 부스 화면에 **전체 이름·학번** 확인 → 스태프 [확인] → 서버가 티켓 전부를 한 번에 처리:
   QR별 확률표로 몬스터 뽑기 → 도감 추가 → 티켓 사용 처리 → 그 QR **다시 열림**.
4. 부스 화면: 볼 흔들림(또는 GIF) 연출 → "축하합니다! ○○몬을 획득했습니다!"
5. 학생 폰: 축하 + **퀴즈** 바텀시트 (그 쌤 문제, 학생당 같은 문제 반복 없음). 정답 → **진화권 +1** (100%).
6. **도감**에서 몬스터를 눌러 진화권 사용 → 서버가 확률로 진화 (1→2: 70%, 2→3: 35%, 실패할수록 확률↑, 일정 횟수 실패 시 확정).
7. 랭킹: 단계 점수 합 (1단계 1점 / 2단계 3점 / 3단계 6점, 희귀 +2, 전설 +10). 동점은 먼저 도달한 사람.

- "도망쳤다" 실패는 **없다**. 확률은 "무엇이 나오는가"에만.
- **전설** = 교장쌤·교감쌤, **진화 없음(1단계)**. 대형 TV의 30초마다 바뀌는 QR로만 잡힘 (`lines.max_stage = 1`).
- 도감 = 일반 15라인 × 3단계 + 전설 2 = 47칸 (라인 수는 운영자 페이지에서 조정).

## 3. 오프라인 원칙
- 인터넷 없이 되는 것: 앱 열기, 도감·지도·랭킹(마지막 저장본) 보기, **QR 스캔**, 가방 QR 보여주기.
- 인터넷이 필요한 것: 첫 로그인, 퀴즈 제출, 진화, 랭킹 갱신. (버튼은 비활성 + 이유 표시. 무한 로딩 금지.)
- **전설 QR은 찍고 90초 안에 서버에 도착해야 인정** → 인터넷 연결 상태에서 찍어야 한다.
- 폰은 IndexedDB에 `snap`(서버가 준 마지막 상태) + `outbox`(아직 못 보낸 스캔)를 저장. 화면 = 둘을 합친 것.
- outbox 항목은 서버가 **nonce별 결과(ack)**를 줘야만 지운다.
- 부스는 학생 폰이 오프라인이어도 처리 가능: 가방 QR 안에 티켓 정보가 다 들어 있다.
- 동기화: 화면이 켜져 있을 때 60초마다 + 앱으로 돌아올 때 + 스캔 직후. 가방 QR을 띄운 동안만 3초마다.
  `sync(p_ver)` — 바뀐 게 없으면 서버가 아주 작은 응답(`same: true`)만 보낸다 (데이터 전송량 절약).

## 4. 데이터 형식 (바꾸지 말 것 — 바꾸면 인쇄된 QR이 다 죽는다)
- **장소 QR**: `https://<사이트>/s#<QR_ID>.<TOKEN>` (예: `/s#A07.k3x9p2mq`). QR 아래에 5자리 수동 코드 인쇄.
  포스터에 **"앱의 볼 버튼으로 찍으세요!"** 문구 필수 (폰 기본 카메라는 다른 브라우저로 열릴 수 있음).
- **가방 QR (v2)**: `PH1/<학번>/<NONCE>.<QR_ID>.<TOKEN>/...` — **대문자·숫자·`.` `/` `-`만** 사용
  (QR 영숫자 모드 → 작고 빨리 읽힘, USB 스캐너가 한글 입력 상태여도 부스가 자모→영문 복원). `-` = 수동 코드 티켓. v1(`|` 구분)도 계속 읽힘.
- 로그인 (0008~): **아무 구글 계정** → 첫 로그인 때 등록 화면에서 **학생(고유번호 6자리 + 이름)** 또는 **외부인(이름만, 랭킹 제외)** 선택 (`register_profile`). 고유번호 `022001` = 22기 1번.
- 학번 로그인: 학번만 입력 → 서버가 `<학번>@code.local` 계정과 8자리 코드를 만들어 **한 번만** 보여 줌 (`create_code_account`, 10분당 생성 수 제한). 다음부터 학번 + 코드. 운영자가 인쇄한 코드(`admin_make_login_codes`, T01 등 → `g:t01`)도 그대로 동작.
- 계정은 서버 함수로만 만든다. Supabase 공개 이메일 가입을 열지 않는다 (남의 이메일 선점 → 구글 로그인 때 계정 탈취 위험). 운영자/부스 권한은 구글로 확인된 이메일에만 (`@staff.test`는 테스트 예외).
- 학번은 본인 입력이라 남이 먼저 등록할 수 있다 → `STUDENT_ID_TAKEN`이면 부스에서 운영자가 재연결, **상품은 학생증 확인 후 지급**.
- 개발용 로그인: 설정 `dev_login`이 true일 때만, 아무 이메일 + 비밀번호 `1234abcd!` (`dev_create_account`).
- 로그인 유지: 세션은 폰에 저장되고 1시간짜리 토큰이 자동 갱신된다. 앱은 오류로 로그아웃하지 않는다 (만료 토큰 → `refreshSession` 후 재시도, `NO_PROFILE` → 등록 화면, 그 밖 → 다시 시도 화면). 로그아웃은 `scope: 'local'` (다른 기기 로그인 유지).
- 고유번호 계정 (0011): 게임 계정 = `<고유번호>@code.local` 사용자 하나. 비밀번호는 학생이 직접 정함(6자 이상).
  - 구글 없이: 번호 + 비밀번호 → 없으면 `create_number_account` 로 만들고 로그인, 있으면 비밀번호 확인.
  - 구글 → 학생: `link_number(번호, 비밀번호, 이름)`. 처음 쓰는 번호면 지금 구글 사용자가 그대로 번호 계정이 됨(mode new). 이미 있으면 비밀번호 확인 후 그 구글 identity 를 번호 계정으로 옮기고 빈 사용자를 지움(mode linked → 클라이언트가 번호+비밀번호로 다시 로그인). 이후 그 구글 계정 로그인 = 같은 번호 계정.
  - 학교 구글 계정(Google 이 확인한 이메일 `022001@hafs.hs.kr`): 등록 화면에 번호 자동 입력, 자기 번호면 비밀번호 즉시 재설정(`p_reset`, 다른 기기 로그아웃 + 다른 구글 연결 해제).
  - 비밀번호 분실: `request_password_reset`(새 비밀번호를 미리 받아 해시로 보관) → 운영자 요청 탭 허용 시 적용 + 로그아웃 + 구글 연결 해제. **허용 전 학생증 확인** (이름은 남도 앎).
  - 부계정은 '외부인'(번호 없음, 랭킹 제외). 구글 사용자의 `register_profile(student)` 는 `USE_NUMBER_LOGIN` 으로 막힘.
- 이스터에그: ① 제목 7번 탭 → 몬스터 퍼레이드 ② 비밀 QR `S01`(지도·카탈로그에 안 보임) → 비밀 몬스터 라인 37 숨바꼬치(도감 완성 조건에서 제외) ③ 도감 완성 → 한 번 축하 화면 + 금테 카드 + 칭호 '도감 마스터' ④ 정각(00분)·마감 1분 전 획득 → 황금 연출 ⑤ 룰렛 꽝이 드물게 777 → 칭호 '럭키 세븐'(서버 `profiles.titles`).
- 참여 기수 (0010): `settings.allowed_gens` = [20,21,22]. 학번 앞 세 자리 = 기수. 범위 밖이면 BAD_GEN (profiles 트리거가 모든 가입 경로를 막음). 앱 ⚙ 설정 맨 아래에 운영자 페이지(admin.html) 링크.
- 운영진 초대 (0009): 운영자 페이지 운영진 탭 → 구글 이메일 + 역할(운영자/부스) → `settings.admin_emails/booth_emails`. 이미 로그인한 구글 계정은 즉시, 아니면 첫 로그인 때 권한. 내 역할은 스스로 못 바꿈.

## 5. 서버 규칙 (보안·동시성)
- 학생은 테이블에 **직접 쓰지 못한다.** 모든 변경은 서버 함수(RPC)로만.
- 모든 변경 RPC: `SECURITY DEFINER`, `search_path=''`, 시작하자마자 그 학생의 `profiles` 행을 `FOR UPDATE`로 잠금 → 같은 학생 요청은 한 줄로 처리 → 중복 지급 불가.
- QR 토큰(`qr_secrets`)·퀴즈 정답(`quiz_answers`)은 학생이 읽을 수 없는 별도 테이블.
- (학생, QR)당 미사용 티켓은 최대 1장 (부분 유니크 인덱스) = 잠금. 하루 같은 QR 최대 `qr_points.daily_cap`(없으면 `settings.qr_daily_cap`)회 — 희귀·전설 QR은 1회.
- 미사용 티켓은 `ticket_ttl_hours` 지나면 만료. 몬스터 후보가 빈 QR의 티켓은 부스에서 취소(잠금 해제) + 현황판 경고.
- 수동 코드 10번 틀리면 10분 잠금. **전설(rotating) QR은 수동 코드 불가**, 토큰은 `rotating_accept_sec`(90초) 동안만 유효.
- 시간 판정은 **서버 시계만**. 같은 가방 QR을 여러 번 읽어도 **처음 결과를 그대로 반환** (멱등).
- 토큰 교체 시 옛 토큰은 `token_grace_minutes` 동안 유효 (이미 찍은 오프라인 티켓 보호).
- `festival_open = false` → 게임 정지 (비상 스위치). `self_redeem = true` → 부스 과부하 때 학생이 앱에서 직접 받기 (안전밸브).
- 나중에 추가하는 함수는 기본으로 아무도 실행 못 함 → 필요한 것만 `grant execute ... to authenticated`.

### 오류 코드 → 화면 문구 (`web/js/sb.js`)
| 코드 | 뜻 |

| BAD_STUDENT_ID / BAD_NAME / BAD_KIND / ALREADY_REGISTERED | 등록 화면 입력 오류 |

| 스캔 ack: invalid_token, already_pending, daily_cap, bag_full, locked, closed, bad_format | 앱이 토스트로 안내 |

## 6. 화면 규칙
- **학생 앱**: 에메랄드 픽셀 스타일. 몬스터 64×64, 기기 픽셀 기준 정수배 확대 (`js/sprites.js`, 갤럭시 소수 DPR 대응). 폰트 Galmuri11 (없는 글자는 시스템 폰트로 자동 대체).
- 홈 맨 위 **"다음에 할 일" 버튼 하나**(퀴즈 → 가방 → 진화 → QR 찾기 순). 첫 로그인: 등록 화면(학생/외부인 + 이름, 개인정보 안내, 랭킹 이름 공개 여부 — 기본 공개, "22기 강*원" 가림) → 게임 방법 4장. 이름은 랭킹·TV·부스 어디서나 `강*원`, 전체 이름은 본인 화면과 운영자 페이지에만.
- 폰 화면: 가로로 넘치는 요소 0개가 기준 (360/390/412px 자동 점검). `[hidden]`은 항상 `display:none !important`.
- 앱 설치(PWA): 로그인 화면·홈 위쪽 "앱으로 설치하기" (크롬은 설치 창, 아이폰은 방법 안내). 설치하면 주소창 없이 열림.
- 이름 공개/비공개는 **오른쪽 위 ⚙ 설정** 맨 위에서 언제든 변경.
- 안드로이드 뒤로가기 = 열린 창 닫기 → 이전 탭.
- iPhone 안전영역, 터치 44px 이상, `prefers-reduced-motion` 존중, 초당 3회 이상 번쩍임 금지.
- 카카오톡/인스타 인앱 브라우저 감지 → 외부 브라우저로 열기 안내. 로그인 안 된 브라우저에서 QR 링크가 열리면 "앱의 볼 버튼으로 다시 찍기 / 5자리 코드" 안내.
- **운영자 페이지**: 픽셀 아님, 일반 관리 화면.

## 6-1. 배틀 데이터 (0012 + 0014, `tools/gen_battle_data.py` → `supabase/seed_battle.sql`, 계열 목록 `tools/roster.py`)
- 계열 = 선생님 1명당 1개, 68개 (1~34 처음 계열 + 43~76 명단에 맞춰 늘린 계열) + 전설·비밀 35~42. 실제 선생님 이름은 저장소에 넣지 않는다 (teacher = '국어 선생님 5' 같은 표시).
- 배틀 타입 15개 (`lines.btype`): 국어·수학·영어·물리·화학·생명·지구·지리·정치경제·윤리·역사·외국어·정보·체육·음악 (+ 보통, 전설). 도감 필터·타입 색 그룹은 `subject`(과목), 상성·기술은 `btype`.
- 상성 = 공격 타입 × 방어 타입 표 (`type_chart`, ×1 칸은 없음): ×2 / ×½ / ×0. 효과 없음: 정치경제→음악, 역사→정보, 체육→수학. 타입마다 ×2 2~3개, 약점 2~4개가 되게 맞춤. 전설은 모두 ×1, 전설끼리 ×2.
- 종족값 6개: 타입 성향 × 단계 총합 (300/405/500, 희귀 +15, 전설 520~640). 라인 번호로 고정한 난수로 6개를 각각 ±14% → 같은 능력치 몬스터 없음 (생성기가 검사).
- 기술 157개 (`moves`, 실제 포켓몬 기술 한국어 이름): 타입마다 물리·특수 2~5개(약→강) + 상태기 3 + 방어기 3. 몬스터마다 4개 (`species_moves`: 공격 2·상태 1·방어 1) 를 단계·라인 번호로 골라서 같은 타입끼리도 다르다. 3단계 두 번째 공격 = 커버 기술(나에게 강한 타입을 많이 찌르는 타입).
- 기술 `effect` (jsonb): `foe_status` par/brn/psn/slp + `chance`, `self`/`foe` 랭크 변화(atk/def/spa/spd/spe/acc), `protect`, `endure`, `rest`, `screen` reflect/light, `break_screen`, `heal` %, `drain` %, `recoil` 1/n, `self_damage` %, `high_crit`, `always_crit`, `self_all_up`.
- 레벨 50 고정 능력치: HP = ⌊(2B+31)/2⌋+60, 나머지 = ⌊(2B+31)/2⌋+5. 요약 화면·레이드 데미지가 같은 식.
- `lines.bonus` = 도감 완성·% 계산에서 빠지는 몬스터 (비밀 37, 탐구 전설 38~42).

## 6-2. 레이드 + 특별 티켓 (0013)
- 레이드 QR = 보통 장소 QR 과 같은 모양 `…/s#R<id>.<토큰>`. 앱은 `R숫자` 이면 티켓 대신 `raid_join`. TV 레이드(`raids.tv`)의 토큰 = HMAC(30초 창, raids.token) → 최근 90초 것만 인정 (사진 공유 방지). 인쇄용은 고정 토큰.
- 공격: 폰이 탭을 세어 4초마다 `raid_attack(id, 탭 수, 몬스터)`. 서버는 지난 요청 이후 경과 초 × `raid_tap_cap`(8) + 8 까지만 인정. 화면의 체력바는 아직 안 보낸 탭만큼 미리 깎아 보여 줌. 레이드 행 하나를 모두가 고치므로 보스 체력 갱신은 `greatest(0, hp - dmg)` 한 줄.
- 탭당 데미지 = max(1, round(10 × 내 몬스터(지금 단계) Lv.50 공격/특수공격 중 큰 쪽 ÷ 보스 방어/특수방어 × 상성)). 몬스터가 없으면 3.
- 끝: 체력 0 → `won`, `raid_min_taps`(10) 이상 탭한 참가자에게 보스 특별 티켓. 시간 초과 → `failed` (`_raid_sweep` 이 아무 레이드 호출 때 정리).
- 시간대 전설: TV(`screen_raids`, 3초마다)가 `raid_slots` 시간 안이면 그 전설 레이드를 자동으로 열고, 끝나면 `raid_cooldown_min` 뒤에 다음 판.
- 특별 티켓 `tickets.special` (raid/dex50/dex100) + `fixed_species`: 가짜 장소 RAID/DX50/DX99 (이름이 ★로 시작 → 부스·앱에서 금빛 표시). 가방 5칸·24시간 만료 제외, 부스에서 보통 티켓과 함께 바뀌고 그 몬스터가 그 단계로 바로 들어옴. 도감(보너스 제외) 50% → 과연기, 100% → 창문기 (`_recompute` → `_dex_rewards`, 한 번씩).

## 6-3. 배틀 (0015)
- 계산은 전부 서버 함수 안 (`_bt_move`, `_bt_turn`, `_bt_resolve`). 폰은 `battle_act(id, {"move": 1~4} | {"switch": 0~2})` 만 보내고, 돌아온 `log` 를 재생한다. 상대 몬스터의 기술·대기 몬스터 이름, 상대가 고른 것은 폰에 오지 않는다.
- 3 대 3 싱글, 교체 가능, 쓰러지면 다음 몬스터를 고름 (남은 게 1마리면 자동). 레벨 50, 3세대 데미지 공식, 자속 1.5, 상성 ×2/×½/×0, 급소 1/16(×2), 명중·선공·스피드(마비 ¼), 랭크 ±6, 마비·화상·독·잠듦, 방어·버티기(연속이면 성공률 ½씩), 벽 5턴, 회복·흡수·반동, PP (다 쓰면 발버둥).
- AI (`_bt_ai`): 기술마다 예상 데미지(위력×상성×자속×명중×능력 비) 점수, 쓰러뜨릴 수 있으면 크게 가산. 상태 이상·능력 올리기·회복·벽은 상황이 맞을 때 점수. ±25% 흔들림.
- 종류: `cpu` 연습 (상대 = 내 팀과 같은 단계의 아무 선생님 몬스터, 보상 없음) / `team` 친구 팀 vs AI (친구의 배틀 QR) / `pvp` 실시간 (신청 → 친구 홈에 "배틀 신청!" → 수락. 한 턴 45초, 안 고르면 AI가 대신).
- 배틀 QR = `BTL.<profiles.battle_code>` (보통 QR 과 같은 모양, `?q=` 링크도 됨). 배틀 팀 = `profiles.battle_team` (없으면 가장 높은 단계 3마리).
- 보상: 이기면 진화권 1장 + `battle_wins` +1 (랭킹). 하루(한국 시간) `battle_daily_max`(3)번, 같은 상대는 하루 1번 (`battle_rewards`). 연습은 보상·랭킹 없음.
- 폰: 홈·배틀 탭에서 8초마다 `battle_inbox` (앱이 보일 때만). 실시간 대전 중에는 2초마다 `battle_state`. 기록 글의 `@0`/`@1` → 내 쪽 '' / 상대 쪽 '상대 '.
